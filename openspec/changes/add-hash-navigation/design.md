## Context

См. `proposal.md` для мотивации и описания проблемы. Расширение функционирует в трех контекстах: всплывающее окно popup (`src/popup/index.html`), отдельная страница опций (`src/options/index.html`) и локальный dev-сервер (`src/dev/`). На текущий момент `ExtensionApp.svelte` хранит историю во внутренних переменных (`route` и `routeStack`), без связи с историей браузера.

## Goals / Non-Goals

**Goals:**
- Реализовать реактивную маршрутизацию на базе URL-хэша для всех экранов расширения.
- Обеспечить полноценную работу кнопок «Назад» / «Вперед» браузера, Alt+Left и боковой кнопки мыши.
- Сохранить минимальный размер сборки без добавления сторонних npm-зависимостей.
- Сохранить текущее поведение UI и структуру компонентов.

**Non-Goals:**
- Сериализация длинных текстов перевода в query-параметры URL (состояние сессии по-прежнему хранится в storage/state).
- Использование HTML5 Path routing (требующее сложных правил перенаправления веб-сервера / CRXJS).

## Decisions

### Decision 1: Кастомный Svelte Store для Hash-роутинга
- **Выбор**: Реализовать легковесный стор `createHashRouter` в `src/lib/router.js`.
- **Обоснование**: Минимальный объем кода (~50 строк), нулевые внешние зависимости, полная адаптация под жизненный цикл Chrome-расширения.
- **Рассмотренные альтернативы**:
  - `svelte-spa-router`: Добавляет лишнюю зависимость и избыточный функционал для небольшого расширения.
  - HTML5 Path routing: Ломает статические пути к файлам расширения (`chrome-extension://<id>/src/popup/index.html`).

### Decision 2: Формат маршрутов и нормализация
- **Выбор**: Канонические маршруты в формате `#/translate`, `#/result`, `#/history`, `#/favorites`, `#/settings`, `#/feedback`, `#/options`.
- **Поведение**:
  - Пустой хэш (`""` или `"#/"`) нормализуется в экран по умолчанию (`#/translate` или `#/options` в зависимости от контекста).
  - Неизвестный хэш перенаправляется на экран по умолчанию.

### Decision 3: Обработка кнопки «Назад» и событий мыши
- **Выбор**:
  - Основной механизм: `window.history.back()` в связке со слушателями `hashchange` и `popstate`.
  - Боковая кнопка мыши: Добавление слушателя на `window` (`mouseup`/`auxclick` с `event.button === 3`) для надежного срабатывания в контексте popup.
  - Fallback: Отслеживание глубины навигации; если `back()` вызывается при отсутствии истории в текущей сессии, выполняется переход на экран по умолчанию.

## Risks / Trade-offs

- **[Риск] Жизненный цикл всплывающего окна (Popup)**: Окно popup закрывается при клике вне его области, сбрасывая историю сессии.
  → *Решение*: Хэш в URL сохраняется при повторном открытии, а `storage.js` сохраняет текущее состояние перевода.
- **[Риск] Двойное срабатывание боковой кнопки мыши**: Если браузер нативно обрабатывает кнопку 3 и вызывает `popstate`, а обработчик также вызывает `history.back()`.
  → *Решение*: Использовать стандартный `popstate` как основной триггер, а слушатель мыши подключать с проверкой предотвращения двойного вызова.
